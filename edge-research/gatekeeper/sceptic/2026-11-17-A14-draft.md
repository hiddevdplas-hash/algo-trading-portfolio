### 1. The mining null (§3.5) tests the wrong thing and has almost no power (BLOCK)
- **What it is:**
  - "Run the generator … on the random-strategy set (A3 menu, random entries)" never exercises the generator's search. A10 already ran random entries through the bars: `null/REPORT.json` random through_g1 = 0.0 and reached_gatekeeper = 0.0, *before* the luck bar. Random entries pay about −0.15 R in costs (A7), so a "0" result is almost certain and shows nothing about mined rules, which are picked *for* positive in-sample results.
  - "Sign-flipped returns" is undefined:
    - mirroring prices keeps all autocorrelation, so a mined mean-reversion rule survives it;
    - flipping each row's trades independently destroys the cross-rule correlation.
  - "Daily budget" (line 43) and "first-month budget" (line 44) contradict each other.
  - "Must be 0" from one month's run is a single yes/no draw. If the true monthly false-finalist rate were 20–30%, one run still shows 0 with 70–80% probability. Showing a rate ≤ 5% at 95% confidence needs 0 hits in about 60 replicates.
  - "Raises the mining bar" doesn't say by how much.
- **Smallest fix:**
  - Null = the real generator on real prices. Store only re-scored trade logs in which r_mid is sign-flipped by one seeded sign per (symbol, entry day), shared by all rows. Costs stay unflipped.
  - `pipeline.py` is pure functions on trade logs, so replicates cost CPU only, with no new rows.
  - Pass condition: 0 null finalists in ≥ 60 replicates at the first month's row count, **and** the replicates' empirical 95th percentile of the best G1 Sharpe ≤ the formula bar at that k.
  - If either fails, raise the quantile by a stated rule until both hold.
  - No real verdict is computed until this is reviewed.

### 2. The generator's search method is not stated (BLOCK: ambiguous, conflicts with a hard rule)

### 4. The bar on day 1 is set at that day's k, so false passes add up over time (serious, numbers)
- **What it is:** k = rows so far, so day 1 is judged at k = 10,000, bar 1.562. For comparison: k = 49 → 1.089, 300k (one month) → 1.805, 1M → 1.884, 3.65M (one year) → 1.966. The draft's 1.56 / 1.73 / 1.89 check out.
- **Evidence:** Each day's batch is judged at its own cumulative k. If every row were an independent G1 test, the chance of ≥ 1 false luck-bar pass is 18.5% in month one, 22.9% by day 90 and 28.3% by day 365, against 5% nominal. That is an upper bound: only G1 rows face the bar, and the rows are correlated. A11.4's re-check at open (at that day's k) only partly offsets this.
- **Smallest fix:** a committed k floor for mining = the planned one-year budget (3.65M → 1.966), i.e. k = max(rows, floor).

### 7. The grammar's filter menu lets in a data-picked regime date and one-sided beta
- **What it is:** "filters from the §6.3 slice menu" includes:

### 8. Locked-period cap and median bar (§3.8): enough against zero edge, but the stated reason is wrong
- **Evidence (normal approximation, locked period about 1.875 years):**
  - A mined finalist must already have walk-forward daily Sharpe ≥ about 1.88. Under zero edge, P(locked Sharpe ≥ walk-forward median) = 1 − Φ(1.88·√1.875) ≈ **0.5%**. The 10th-percentile bar gives about 2.5%.
  - §9's 9–37% applies to slow main-pipeline strategies, not to mined finalists.
  - For a +0.10 R walk-forward expectancy, zero edge passes the median bar 19 / 11 / 4 / 1% at 60 / 120 / 250 / 400 trades a year.
- **The real cost is power:**
  - A real edge at the walk-forward's size passes 50%. A mined edge that has shrunk to Sharpe 1.0 (winner's curse) passes about 11%.
  - With the luck bar at 1.88, a +0.05 R edge essentially never passes. A +0.10 R edge passes about 1% at 150 trades a year and 43% at 400.
- **Expected yield is close to zero; write that in A14 now** so nobody later argues the bar down.
- **Two gaps:**
  - The draft doesn't say which finalists get the 2 monthly slots. Fix: first-come by G2 pass time, no carry-over, no gatekeeper choice.
  - All opens share one 22-month locked period, and each open shows how 2025–26 behaved (A1.5 contamination). Fix: for mined opens, `OPENS.md` records only pass/fail and the bar values; per-symbol and per-direction locked P&L goes in `mining/` only.
