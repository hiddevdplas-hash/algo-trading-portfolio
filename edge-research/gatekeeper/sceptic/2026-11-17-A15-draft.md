## New findings, most serious first

**A. The rule that a lower null bar can come "by a later addendum, before any mined verdict" breaks the DESIGN change rule. (BLOCK)**
- **Where:** A15 §4, lines 42–43, against DESIGN lines 10–11 ("never changed for an idea whose result has already been seen").
- **Evidence:**
  - By the time the null exists, all 50,000 screen rows exist.
  - Each runner row already carries `metrics.M0.daily_sharpe` for the full period, plus `by_year`, `by_symbol`, `long` and `short` (I checked a real screen row).
  - The judged window (2016-11 → 2024-12) is 8.17 of the screen's 10.17 years, about 80%. So each rule's judged Sharpe can be read almost directly off its row.
  - `LOG.md` also carries "how many rules at each stage".
  - "Before any verdict is computed" therefore does not mean "before results are seen". Anyone writing that addendum can count how many rules sit between a candidate lower bar and 1.68.
- **Smallest fix (pick one):**
  - (a) Delete the lowering clause. The bar is then max(formula at k, the null-derived bar), period.
  - (b) Write the lowering rule into A15 now, as a mechanical rule with no discretion. For example: "with ≥ 200 replicates, z* = the replicates' 95th percentile of the best standardized judged Sharpe, if 0 null finalists lie above it; never below z at k_eff = …".
- (a) is the safe choice.

**B. The null as written cannot replay the judging, its test statistic is undefined, and the raise rule never finishes. (BLOCK)**
- **Where:** A15 §3.1 (compact array) and §5.
- **Replay gap:**
  - The compact array holds entry time, symbol, side, r_mid and r_net per mode.
  - Judging's daily Sharpe and the Newey–West variance ratio (VR) bucket trades by **exit** day (`pipeline.py:282-287`, `unseen_daily` 248-255). The hold-time bar needs `exit_t − entry_t` (263-268). Neither can be computed without `exit_t`.
  - Modes M1–M3 hold different trades from M0 (blocked entries, early flattening), so "r_net per mode" on one trade list is not the real per-mode log.
  - Fix: store **one array per mode** with entry_t, exit_t, symbol, side, r_mid and r_net_ftmo. Cost = r_mid − r_net. Use the same sign for a given (symbol, entry day) in every mode.
- **Statistic undefined:** "the best judged Sharpe" doesn't say over which rules, which modes, or how a rule's VR is handled. The real bar is σ0·max(1, √VR)·z, so comparing raw null Sharpe with the VR-1 bar mixes units.
  - Fix: per replicate, take the maximum over null rules that are green at the screen and pass every judging bar except the luck bar. Take it over modes M1–M3, which matches eligibility at any firm (rule D). Use the standardized statistic Sharpe / (σ0·max(1, √VR)), and compare it with z_k = Φ⁻¹(0.95^(1/k)) = **4.748 at k = 50,000**.
  - Also say that G2 is not replayed, so a "null finalist" means a null rule that passes screen and judging (this is conservative).
- **Raise rule never finishes:**
  - Setting the bar at the 95th percentile of 60 replicate maxima leaves about 3 replicates above it by construction. If any of those passes the other bars, "0 null finalists" fails again.
  - Fix: z* = the larger of z_k and the highest standardized Sharpe of any null finalist in any replicate, plus a small step. Both conditions then hold, and the rule only ever raises the bar.

**C. k is ambiguous. (BLOCK)**
- **Where:** §4 "k = max(50,000, every mining row written)", against §3.4 "every verdict uses the same final k" and the A11.4 re-check at the open.
- **Problem:**
  - G2 noise, cost and swap0 runs and parameter-neighbour runs are ledger rows. The null calibration wrote them too: 2,565 `null-stress-noise` rows.
  - So rows pass 50,000 while verdicts are being given, and later candidates face a higher bar than earlier ones.
  - An engine or composer fix that reruns the sweep would double the rows.
- **Fix:**
  - k = max(50,000, distinct drawn rules with a screen row) **+ main real rows** (49 today, which moves the bar by less than 0.001; see H). Freeze it when the null is reviewed.
  - G2 rows and reruns of the same drawn rules don't change it.
  - Any later sweep counts all mining rules ever drawn, and sweep-1 candidates not yet opened are re-checked at that k.

**D. G2 "neighbouring values = drawn rules nearest in the grammar" is undefined and in practice empty.**
- **Where:** §3.3.
- **Why:** Symbol sets alone number C(39,1..4) ≈ 92,000, before timeframes, blocks and their parameters. The grammar is far larger than 50,000 draws, so a rule's exact one-step neighbours are almost never drawn. "Nearest" would then be a different rule, and the 70% keep test would mean nothing.
- **Fix:** for each rule that passes judging, run its explicit ±1-step neighbours on each parameter (same symbols, timeframe and blocks) as G2 rows. Per C, they don't count in k.

**E. The draw itself isn't bound; the spec hash is not enough.**
- **Where:** §2 ("refuses any mining job without the generator's spec hash").
- **Why:** A hand-picked rule written in the grammar carries the same spec hash. That is the loophole finding 6 asked to close ("lane=mining to skip the card rules").
- **Fix:** before the first job, commit the sampler code hash, the seed and the SHA-256 of the full 50,000-rule list. The runner refuses any mining job whose rule id and definition hash are not in that list. Use one engine hash and one composer hash for the whole sweep. A change that alters results voids and reruns the whole sweep (k per C).

**F. Trading both sides is not the same as being balanced. Beta and the long/short loophole remain.**
- **Where:** §1.3, with `pipeline.py:357-359` (`or not m.any()`: a side with no trades passes).
- **Why:**
  - A two-sided trend-filtered rule on US500, USTEC or XAUUSD over 2016–2024 is mostly long and earns drift.
  - The G2 side bar is only "no side below −0.05 R per trade". So 80% longs at +0.15 R and 20% shorts at −0.04 R pass, and so does a rule whose short leg never fires.
  - The sign-flip null removes drift, so beta counts as "edge" against it.
- **Fix:**
  - The spec requires mirror-symmetric blocks (the short condition is the long condition on negated price).
  - For mined rules, the long/short bar fails a side with fewer than about 25% of trades, and does not pass an empty side.
  - Widen the anchored-average exclusion to any anchored average or band (session, day, week, intraday dual), as §3.7 lists.

**G. A cost-model gap that a 50,000-rule search will find (test validity, moderate).**
- **Evidence:** `engine/costs.json` `addon_detail`. Fourteen symbols lack a 2020-measured FTMO add-on, and several research symbols are flat across the day, for example US500 0.078 bp, XAUUSD 0.85 bp, DE40 0.33 bp (all from "feed report 2025-07 → 2026-10 (flat)").
- **Why it matters:** where the add-on was measured by the hour it varies a lot: JP225 0.69–2.21 bp by NY hour. Time-of-day blocks searched 50,000 times will select hours where a flat add-on understates FTMO's spread.
- **Fix:** for mined finalists on symbols with a flat or unmeasured add-on, add a raise-only G2 test at spread × 2 in hours outside the cash session, or run G3 (firm feed check on research-period FTMO ticks where they exist) before the locked open.

**H. The firewall is open in the reverse direction, and the backstop is too narrow.**
- **Grammar author:** the mining session reads STATUS, LOG and DIGEST (CLAUDE.md line 10), so it knows which main ideas were amber (2001 and 3000 under A12) and the A1.5 history to mid-2026. A grammar shaped by that carries selection that the mining k doesn't count.
  - Fix: the spec states A1.5 and §3.7 compliance, and the sceptic reviews `SPEC.md` once before the draw. The mining session doesn't read `ledger/`, `results/`, `IC-WATCH.md` or batch reports.
  - Cheap insurance: add the main real rows to the mining k, as in C.
- **Backstop:** "same symbol set" with an exact match almost never triggers.
  - Fix: any shared traded symbol, plus the same timeframe, plus the same entry-block family.

**I. Judging is in-sample. The design holds, but A15 has to say so.**
- **What this means:** the 2016-11 → 2024-12 window is not unseen in any sense. It is 80% of the screen sample, and the screen picks on it.
- **Why it's still valid:**
  - With k = all 50,000 draws, the luck bar caps the chance that any zero-edge rule's judged Sharpe clears it, whatever the screen does. The screen can only remove rules.
  - The empirical null checks the tail at z = 4.75, where the normal fit is weakest.
  - The sign flip is conservative here in three ways:
    - Trade outcomes are bounded at about −1 R, so they skew positive. For positive skew, the t-statistic's right tail is thinner than the flip assumes.
    - Flipping per (symbol, day) understates the correlation between rules: rules on different symbols, and multi-day holds entered on different days, are flipped independently. That raises the null's maximum.
    - It is right for multi-symbol rules as a check that only raises the bar. It would **not** be valid evidence for lowering the bar, another reason to delete the clause in A. If a lowering rule is ever wanted, use one sign per entry day across all symbols, which keeps the correlation between symbols intact.
- **What is lost:**
  - The locked period is the only out-of-sample evidence.
  - G2's fx2015 test is vacuous (the judged window starts after 2015).
  - The "≥ 200 unseen trades", yearly-blocks and without-best-year tests are all in-sample.
- **Fix:** say "in-sample at full multiplicity" in place of "unseen", and add §6.6 to the overrides in 1.4.
- Judging over the full 10.17 years would be an equally valid choice (σ 0.317, bar 1.51, more power). If wanted, decide it now; never after rows exist.

**J. A14 conditions carried into the grammar (minor).**
- COT blocks need A14.2.3(a), the revision bound, done before the sweep starts, not only "features in the engine". They also need (b): levels or ≥ 52-week percentiles only.
- Context blocks use only the 39 firm symbols; AUS200, F40, HK50 and US2000 are excluded (A14.1.5).

**K. The ledger audit (minor).** A daily SHA-256 of a file that keeps growing can't prove that yesterday's content is still the start of today's file.
- Fix: commit (byte length, SHA-256) per file per day. The audit hashes today's file cut to yesterday's length.
